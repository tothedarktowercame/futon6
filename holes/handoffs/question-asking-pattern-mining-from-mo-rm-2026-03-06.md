# Handoff: Mining a Pattern Language of Research Question-Asking from MO Reverse Morphogenesis Data

Date: 2026-03-06
Source: Claude Opus session surveying MO reverse morphogenesis output
Target: Codex (long-running mining + validation)

## Objective

Mine a **pattern language of research question-asking** from MathOverflow
reverse morphogenesis data, cross-validated against the First Proof journey
and (eventually) FrontierMath problems.

The deliverable is a set of named, reusable question-asking patterns — each
describing *when* a particular kind of question arises in research mathematics,
*what form* the question takes, and *what makes it productive or unproductive*.

## Where the data lives

### MathOverflow reverse morphogenesis (primary source)

```
~/code/storage/mo-processed-gpu/reverse-morphogenesis.json
```

- **Format**: JSON array, 95,321 entries, ~400MB
- **Each entry** has this shape:

```json
{
  "entity_id": "se-mathoverflow-32",
  "question_id": 32,
  "analysis": {
    "raw": "<LLM output text>",
    "parse_error": "invalid JSON"   // present on ~93% of entries
  },
  "raw": "<full LLM output text>"   // sometimes here instead of analysis.raw
}
```

- **IMPORTANT data structure notes**:
  - Only ~6,391 entries have clean JSON parses (6.7%). The rest have
    `parse_error` in the `analysis` dict.
  - However, **nearly all 95K entries have usable text** in the `raw` field
    (or `analysis.raw`). The LLM (Llama-3-8B-Instruct) generated good
    situation descriptions; it just didn't wrap them in valid JSON.
  - The text typically contains sections labeled `IDENTIFY THE STRUCTURE`,
    `CLASSIFY QUESTION QUALITY`, `INDUCE SITUATION S`, and `VERIFY`.
  - To get the situation text, search for `"situation s"` (case-insensitive)
    in the raw text and extract ~800-1000 chars from that point.
  - The `raw` field may be at top level OR inside `analysis.raw` — check both:
    ```python
    raw = entry.get('raw', '') or entry.get('analysis', {}).get('raw', '')
    ```

## How the initial survey was done

### Method

1. Loaded the full 95K MO JSON into memory (~400MB, fits in RAM).

2. For each entry, extracted the raw LLM text from `entry.get('raw', '') or
   entry.get('analysis', {}).get('raw', '')`.

3. Located the "SITUATION S" section via case-insensitive string search and
   extracted ~800-1000 chars of situation text.

4. Applied keyword-based trigger classification — checking for presence of
   specific words in the situation text. Each entry can match multiple patterns.
   The keywords used:

   | Pattern | Keywords checked |
   |---------|-----------------|
   | EXISTENCE_WONDER | `"wonder"` near `"if"` or `"whether"` |
   | CONNECTION_SEEKING | `"connection"`, `"relationship"`, `"bridge"` |
   | CURIOSITY_FROM_SURPRISE | `"surprise"`, `"unexpected"`, `"curious"` |
   | GENERALIZATION_PROBE | `"generalize"`, `"extend"`, `"broader"` |
   | CLASSIFICATION_QUERY | `"classif"` |
   | COUNTEREXAMPLE_HUNT | `"counterexample"`, `"counter-example"` |
   | FAILURE_UNDERSTANDING | `"fail"`, `"break"`, `"does not"` |
   | COMPUTABILITY_QUESTION | `"comput"` + (`"efficient"` or `"algorithm"` or `"calculat"`) |
   | CONJECTURE_TESTING | `"conjecture"` |
   | SHARPNESS_TESTING | `"optimal"`, `"best"`, `"sharp"`, `"tight"` |
   | ANALOGY_TRANSFER | `"analogy"`, `"analogous"`, `"similar to"` |
   | OBSTRUCTION_IDENTIFICATION | `"obstruction"`, `"obstacle"`, `"barrier"` |

5. Cross-referenced the MO frequency distribution against 8 candidate
   question-asking patterns extracted from the First Proof process pattern
   documents.

### Limitations of this initial survey

- **Keyword classification is crude**. "Curious" catches genuine curiosity but
  also boilerplate LLM phrasing ("they are curious about..."). Many situations
  will be misclassified or multi-classified. A proper mining pass should use
  embeddings + clustering, not keywords.

- **The situations are LLM-generated**, not human-written. They're constrained
  by actual MO questions (which are real), but the situation narratives are
  Llama-3-8B confabulations. They tend toward a formulaic "Imagine a
  researcher named Alex..." pattern. The *structure* of the situations is
  informative even when the *narrative* is generic.

- **Selection bias**: The 6.7% parse rate means the successfully-parsed
  entries (with structured JSON) are biased toward cleaner Q&A pairs. The
  raw-text extraction recovers most entries but the LLM quality varies.

- **No validation yet** against actual research trajectories. The First Proof
  patterns were identified post-hoc from a single proof campaign. They need
  to be tested on new problems (FrontierMath).

## Key finding: two layers of question-asking

### Layer 1: Content-facing questions (what MO captures)

These are the questions researchers ask publicly. MO frequency:

| Pattern | Count | Example |
|---------|-------|---------|
| EXISTENCE_WONDER | 51,139 | "Does a group with property X exist?" |
| CONNECTION_SEEKING | 31,179 | "What's the relationship between X and Y?" |
| CURIOSITY_FROM_SURPRISE | 14,741 | "I noticed X behaves unexpectedly under Y..." |
| GENERALIZATION_PROBE | 12,818 | "Does theorem T extend to setting S?" |
| CLASSIFICATION_QUERY | 9,492 | "What are all manifolds satisfying P?" |
| COUNTEREXAMPLE_HUNT | 5,040 | "Is there a ring where this isomorphism fails?" |
| FAILURE_UNDERSTANDING | 3,859 | "Why does method M break for non-integral schemes?" |
| COMPUTABILITY_QUESTION | 3,669 | "Is there an algorithm to compute X?" |
| CONJECTURE_TESTING | 3,532 | "Is the ABC conjecture equivalent to...?" |
| SHARPNESS_TESTING | 2,352 | "Is this bound tight?" |
| ANALOGY_TRANSFER | 1,586 | "Does the p-adic analog of X hold?" |
| OBSTRUCTION_IDENTIFICATION | 581 | "What obstructs extending Kuranishi structures to...?" |

### Layer 2: Process-facing questions (what First Proof captures)

These are the questions researchers ask *while working* but rarely post publicly.
They came from the actual proof campaign (p4/p6/p7 process patterns):

| Pattern | MO frequency | First Proof productivity |
|---------|-------------|------------------------|
| STRUCTURAL PROBE ("does this mechanism actually work?") | ~3.5K (partial) | High |
| THEOREM APPLICABILITY ("do the hypotheses match?") | ~0 | Very high |
| FAILURE CHARACTERIZATION ("why does this fail structurally?") | ~3.9K (partial) | Very high |
| TENSION DISSOLUTION ("can I resolve conflicting requirements?") | ~0 | Critical |
| KERNEL IDENTIFICATION ("what's the one remaining lemma?") | ~0 | Critical |
| LANDSCAPE SCOUT ("what does the territory look like numerically?") | ~3.7K (partial) | High |
| TECHNIQUE LANDSCAPE ("what methods get close, where do they break?") | ~1.6K (partial) | High |
| CONFIDENCE INVERSION ("am I confident about the wrong things?") | ~0 | Very high |

The highest-leverage patterns (THEOREM APPLICABILITY, TENSION DISSOLUTION,
KERNEL IDENTIFICATION, CONFIDENCE INVERSION) are **absent from MO**. They're
process questions, not content questions. A researcher using these as a
checklist would be asking questions that peers typically don't surface.

## Proposed mining + validation plan

### Phase 1: Proper clustering of MO situations (mining)

1. Extract all ~95K situation texts from the MO RM data.
2. Embed them (BGE-large or similar — already available in the pipeline).
3. Cluster (HDBSCAN or k-means with silhouette tuning).
4. Name the clusters — each cluster is a candidate content-facing pattern.
5. Compare cluster structure against the 12-pattern keyword taxonomy above.
   Where do they agree? Where do clusters split or merge the keyword categories?

**Output**: `data/question-patterns/mo-situation-clusters.json` —
cluster assignments, centroids, representative examples.

### Phase 2: Cross-reference with First Proof (validation)

1. Take the 8 process-facing patterns from the First Proof.
2. For each, find the closest MO situation clusters (by embedding distance).
3. Identify which process patterns have MO analogs (partial matches) and
   which are genuinely absent from the content-question layer.
4. For partial matches, examine the gap: what does the process pattern add
   that the MO content question misses?

**Output**: `data/question-patterns/process-content-alignment.json`

### Phase 3: Pattern language document (synthesis)

Write the pattern language as a set of named patterns, each with:
- **Name** (e.g., TENSION DISSOLUTION)
- **Layer** (content-facing / process-facing / both)
- **When it fires** (trigger conditions)
- **Question form** (what the question looks like)
- **Quality test** (how to tell if the question is well-formed)
- **Evidence** (MO cluster ID + count, First Proof instances)
- **Productivity assessment** (from First Proof: how often did asking this
  question change the research trajectory?)

**Output**: `data/question-patterns/research-question-pattern-language.md`

### Phase 4: FrontierMath probe (validation on new problems)

Take the 3 FrontierMath pilot problems + the superpod trial results and
run through the pattern language as a question-generation checklist.
Score: did the checklist surface questions that would have been productive?
Did it miss any?

**Output**: `data/question-patterns/frontier-validation.md`

## Notes for Codex

- The MO JSON is ~400MB. It fits in memory on a 16GB machine but budget for
  it. If memory is tight, stream with `ijson` instead of `json.load`.
- The `raw` field text is messy — Llama sometimes cuts off mid-sentence,
  sometimes repeats the prompt. Trim and clean before embedding.
- The "Imagine a researcher named Alex" framing is an artifact of
  Llama-3-8B's style, not meaningful content. Focus on the *structural*
  elements of the situation (what triggered the question, what kind of
  mathematical object is involved, what understanding is sought).
- The math.SE data (~800K entries) could be used for contrast (undergrad vs.
  research question patterns) but is secondary to MO for this task.
- The existing 25 math-informal patterns in `data/pattern-tags.edn` are
  *proof* patterns, not *question-asking* patterns. They're related but
  distinct — a proof pattern like `argue-by-contradiction` implies a
  question-asking situation but is not itself a question pattern.
